## Análise das correções

1. A expressão anterior de target em `images.yml` não conseguia retornar uma
   string vazia para cognition: `condição && '' || matrix.target` sempre
   terminava no fallback. O workflow pedia o estágio `cognition`, que não
   existia no Dockerfile. Usar diretamente `matrix.target` e nomear o estágio
   `FROM ... AS cognition` resolve a incompatibilidade. Os quatro targets
   continuam na matriz; nenhum build foi desativado.
2. Os gates de ambiente e qualidade executavam `rg` sem instalar essa
   ferramenta no runner. O coletor Node compartilhado remove essa dependência
   externa. Mantém os diretórios de origem, extensões e recursão; erros de
   leitura ou caminho ausente continuam interrompendo a execução. Arquivos
   ocultos, links simbólicos e diretórios gerados não entram na coleta.
3. Comparei os conjuntos de arquivos do comando anterior e do coletor novo
   no repositório final: **107 arquivos de ambiente e 56 de qualidade,
   exatamente iguais**. Não houve redução da cobertura para obter aprovação.
4. Os novos testes executam o gate com PATH sem ferramentas externas. O caso
   positivo valida uma referência aninhada; o negativo exige exit code 1 e
   os nomes das duas variáveis ausentes, inclusive no arquivo de configuração
   direto. A fixture também verifica que o conteúdo do `.env` privado não é
   exposto. `npm test` passou a executar esses testes além dos anteriores.
5. O primeiro build corrigido passou, mas sua execução real encontrou
   `PermissionError`: sem variável injetada, `Store` tentava criar `/app/data`,
   sem permissão para o usuário atlas. O Dockerfile agora define
   `ATLAS_DATA_DIR=/data`, diretório já pertencente ao UID 10001, coerente com
   os arquivos Compose. A variável continua configurável pelo operador.
6. O sensor `scripts/check-cognition-image.py` inicia Uvicorn dentro da imagem
   e exige health 200, acesso anônimo negado com 401 e documentos autenticados
   com 200. O workflow executa o sensor sem rede externa: carrega a imagem
   cognition em builds sem publicação e a puxa após publicação quando
   necessário. Não alterou as verificações das outras três imagens. O sensor
   falha se o processo sair, a prontidão não chegar ou uma resposta divergir;
   a correção não foi feita injetando um diretório alternativo no teste.
