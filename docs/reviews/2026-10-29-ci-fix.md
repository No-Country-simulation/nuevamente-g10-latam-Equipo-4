## Causas e correções

### Target de imagem

A expressão `condition && '' || matrix.target` devolve `matrix.target` também
quando a condição é verdadeira: string vazia é falsa. Assim o workflow passa
`--target cognition`, mas o Dockerfile Python não declarava esse estágio.
Agora o estágio chama-se `cognition` e o workflow usa o target explicitamente.
Nenhum build da matriz foi removido.

A execução real também encontrou um problema de inicialização da imagem isolada:
o default relativo `data` aponta para `/app/data`, sem permissão de escrita para
o usuário atlas. A imagem agora define `ATLAS_DATA_DIR=/data`, diretório já
criado para esse usuário. O Compose já usava esse mesmo caminho; a correção
alinha o default da imagem sem depender de configuração implícita do host.

### Ferramenta implícita nos gates

`check-env` e o coletor de qualidade chamavam `rg` sem instalá-lo ou declará-lo
como requisito do runner. A reprodução com PATH sem rg falha com ENOENT/exit1.
Um runner limpo não deve depender das ferramentas instaladas na máquina de quem
programa. A enumeração agora usa somente Node, já declarado no workflow.

O helper percorre os mesmos roots, inclui arquivos diretos e subdiretórios,
não segue symlinks e ignora os mesmos diretórios gerados/ocultos. A comparação inicial
dos conjuntos antigos e novos encontrou106 arquivos ENV e56 de qualidade;
após acrescentar o sensor de inicialização, são107 arquivos ENV, ainda com
igualdade entre o coletor antigo e o novo. O contrato segue cobrindo62 referências e o sensor616 símbolos.

Os dois testes novos verificam execução sem executáveis externos e falha real
quando uma variável falta no exemplo, em módulo aninhado e config direto.
O arquivo `.env` privado não é lido nem impresso. Nenhum assert foi afrouxado,
nenhum gate foi removido e nenhuma baseline/threshold foi alterada.
